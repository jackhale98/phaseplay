# Decisions

One line per decision: date — decision — why.

- 2026-11-16 — SvelteKit SPA on GitHub Pages + Worker/D1 API on api.phaseplay.app — passkeys bound to phaseplay.app from day one; move to Cloudflare is DNS-only.
- 2026-11-16 — One shared D1 database, no app-level encryption — tenancy enforced in code and tests; revisit per-team DBs if adoption grows.
- 2026-11-16 — No health/concussion data — legal and privacy risk outweighs value.
- 2026-11-16 — Drills reuse the play diagram engine (`mode: 'drill'`) — one renderer, editor and export pipeline; drill details live on the drill row, not in the diagram.
- 2026-11-16 — Match and practice timing come from timestamped event logs reduced by pure functions — accurate through screen lock, offline-safe, conflict-free sync.
- 2026-11-16 — Launch straight to Cloudflare: one Worker serves the SPA (Workers static assets) and the API on the same origin, `phaseplay.app/api/*`; M8 folded into M0 — no CORS or preflights, real security headers from day one, one atomic deploy/rollback, `__Host-` cookie on the app origin. Supersedes the GitHub Pages + `api.phaseplay.app` plan.
- 2026-11-16 — Raw D1 prepared statements instead of Drizzle — exact control of the ≤6-query budget (sync is one `json_group_array` statement), bulk writes via `json_each`, fewer abstractions; schema of record is `apps/api/migrations/*.sql`, row mappers in `apps/api/src/db/rows.ts`.
- 2026-11-16 — Memberships have their own id (`member id`), unique on (team_id, user_id) — imported/pending names can be put on sheets and RSVP'd for by staff before they join; claiming sets `user_id`.
- 2026-11-16 — Recurring trainings are materialised into concrete events (≤ 1 year, ≤ 160) — RSVPs, sheets, ICS and sync all work on plain events; skip/override = edit/cancel one event; deleting a series soft-deletes its future events.
- 2026-11-16 — Delta sync cursor is the server time at query start, re-read with a 10 s overlap; the client merges idempotently by id — rows committed concurrently with a sync are never missed.
- 2026-11-16 — Team sheets keep a `published` snapshot; players only ever receive the snapshot, so coaches can keep editing after publishing without leaking drafts.
- 2026-11-16 — SvelteKit 3 (current major): config in `vite.config.ts`, `#lib` subpath imports (+ TS `paths`), `$app/env`, `$app/manifest`; native SvelteKit service worker instead of `@vite-pwa/sveltekit` (smaller, full control of the "update available" flow).
- 2026-11-16 — Font: Archivo variable (wght axis, Latin subset, 34 KB woff2, OFL) — sporty grotesque with tabular figures, inside the 60 KB budget.
- 2026-11-16 — Front-row cover default follows World Rugby Law 3: 15 or fewer players → 3, 16–18 → 4, 19–22 → 5, 23 → 6 front-row-capable players (7s: 3); configurable per event (`settings.frontRowCover`).
- 2026-11-16 — Test-only login is behind a build-time `__TEST_AUTH__` define (true for local dev and `--env test`, false for production) and refuses ENV=production at runtime; CI and the post-deploy smoke test both assert it's absent.
- 2026-11-16 — A 7s tournament event records consecutive games as period pairs (1–2 = game 1, 3–4 = game 2, …, up to 6 games / `MAX_PERIODS = 12`) in one append-only log. In the 20-minute red-card law trial, a `sub` whose `offId` is the sent-off player brings a replacement on once 20 game-minutes have passed.
- 2026-11-16 — Deploys run on Cloudflare Workers Builds (Git integration), not GitHub Actions — no Cloudflare token in GitHub; the D1 database is auto-provisioned by name on first deploy; Actions stays CI-only plus a nightly production smoke test.
- 2026-11-16 — Public demo at /demo: visitors sign in as a fixed, passkey-less demo coach of a fictional team; the API rejects all writes from that account, and the app keeps demo edits in memory. One shared demo refreshed daily (≈1.5k rows written/day) instead of a team per visitor, which would exhaust D1's free write quota.
- 2026-11-17 — No live player view during practice (product call: phones stay off the pitch); players see the shared plan beforehand.
- 2026-11-17 — Outbox pins each versioned edit's base version at edit time instead of resolving it at send time, so a background sync between edit and send can't turn a conflict into a silent overwrite.
- 2026-11-17 — Live practice sessions are shared by all staff (assistant coaches coordinate forwards/backs splits). Advance/skip/end events get ids derived from the run's start event and step index, so several phones auto-advancing or tapping Next together merge into one event; players still have no live view.
- 2026-11-17 — Landing and privacy pages ship no JavaScript (`csr = false`); the signed-in redirect and saved theme run in one inline script allowed by its CSP hash (computed in vite.config.ts), and page CSS is inlined. Lighthouse mobile: LCP 1.2 s, perf 99–100, a11y 100, best practices 100.
- 2026-11-17 — Debounced autosaves (sheets, plans, plays, drills) pin the base version when a burst of edits begins, not when the save fires.
- 2026-11-17 — Permissions v2: an `admin` main role (e-board: everything but deleting the team) plus named team roles that add only `GRANTABLE` permissions. Ownership moves by nominate-then-accept; an admin can claim it after the owner has been inactive 30 days. Team-role grants are folded into the existing membership query, so authorization still costs one query.
- 2026-11-17 — Deleting a team is gated on `team.delete` (owner only) in the route table, not `team.manage`, now that admins have `team.manage`.
- 2026-11-17 — Team emblems live in D1, not R2 (no new service to enable): the browser fits uploads into 256 px and encodes WebP/PNG (SVG is rasterised, never stored); the API checks magic bytes, caps 200 KB, and serves them `immutable` behind `?v=crestVersion` with `nosniff` and a sandbox CSP.
- 2026-11-17 — RSVP notes follow the main role (staff), not team-role grants: `availability.view` from a team role shows replies only.
- 2026-11-17 — Workers Builds deploy command is `pnpm cf:deploy`; `pnpm deploy` is a pnpm built-in and never runs the package script.
- 2026-11-17 — Removed the TeamSnap CSV import (route, permission `import.run`, page, parsers); pending names are added by hand.
- 2026-11-17 — US East Coast first: new teams default to America/New_York (US zones listed first); the demo team runs on New York time.
- 2026-11-17 — "Who's going" is a team setting (`teams.rsvp_visibility`: counts | games | all). Sync filters reply rows for players by it in SQL; changing it bumps every membership so devices full-sync. Notes stay staff-only regardless.
- 2026-11-17 — Weekly series are editable as a whole ("All upcoming"): times, days, details, type and end date apply to future sessions only; sessions keep their id (and replies) when their date stays, dropped dates are soft-deleted, new ones inserted, in one UPDATE … FROM json_each plus one INSERT. Any non-game event can repeat.
- 2026-11-17 — No screen pans sideways on phones: html/body `overflow-x: clip`, sheets scroll vertically only, grid tracks are `minmax(0, 1fr)`, iOS date/time inputs use `appearance: none`, and inputs are ≥16px on touch screens (stops iOS focus-zoom). An e2e test checks scroll width on phone layouts.

- 2026-11-17 — Emblem background removal runs in the browser (lib/crest-bg.ts): edge-colour detection, flood fill from the edges (enclosed white survives), despeckle, and alpha unmixing at the boundary. No ML model or service; photos or busy backgrounds are left as is, and the coach previews light/dark and can switch it off before saving.
- 2026-11-17 — Brand kit installed: ribbon text outlined to paths at build time (fontTools, Archivo wdth 125 / wght 800), a 2 KB caps-only wordmark font, the mark inlined for ≤ 64 px, the play loader as the single loading state, and brand colours as the base tokens (Paper background, Ink text, Pitch accent, Amber secondary). Team colours still override the in-app accent.
- 2026-11-17 — Join-invite links are stored (invites.token, staff with invites.view only, returned only while the invite is live) so they can be copied again; relink links stay hash-only. Invites are short-lived, capped and revocable, so keeping the link is worth the convenience.
- 2026-11-17 — Premade rugby content follows a coach's audit: no forward passes in drills, Law 18/19/12 positions in presets (tests in packages/diagram), a below-the-sternum tackle cue in every contact drill, and US labels (Defense, flag) in content strings only. The lineout and scrum view sizes stay as they are; the player and editor grow to fit every token, and the demo plays set their own `viewport`.
- 2026-11-17 — Archive, not delete, for plays and drills (archived_at): hidden from lists, pickers and the command palette, still rendered where referenced (plans, sessions). Built-in drill templates and play presets are hidden per team (teams.hidden_templates), gated per key by drills.manage / plays.manage.
- 2026-11-17 — Kit (M9): an item's `version` covers its details only (PUT with If-Match, and split, which changes the quantity). Holder and status move through the action routes, which compare-and-set on the status and holder they read, so a details edit and a handover never 409 each other. Every action writes its history rows in the same batch under the same guard. Handover accepts race to one winner (a repeat accept is 409, not a replay); an expired request is taken over in place by the next one (upsert on the one-open-per-item index). Accept/decline are queued offline but never move the item until the server answers.
- 2026-11-17 — Landing LCP budget raised from 1.5 s to 1.8 s (owner approved). The hero phone screenshot is the LCP element and sat ~40 ms over under Lighthouse's simulated slow 4G with 4× CPU; real-world load is well under 1 s, so the extra engineering to scrape under 1.5 s wasn't worth it.
- 2026-11-17 — Web Push without the `web-push` package (Node-only): RFC 8291/8292 with WebCrypto in apps/api/src/lib/push. The VAPID key pair is made on first use and kept in D1 `server_keys` (no secret to set up; rotating it means every device re-subscribes). Pushes go through `push_queue`, ≤ 25 sends per invocation (Workers Free subrequest/CPU limits): the first batch via waitUntil, the rest by a 5-minute cron that also queues reminders and kit-at-risk. Endpoints are restricted to known push-service hosts.
