# Runbook

## Deploys (Cloudflare Workers Builds)

Cloudflare builds and deploys straight from GitHub, so no API token lives in GitHub. GitHub Actions runs CI only.

**One-time setup** (Cloudflare dashboard, with GitHub already connected):

1. Delete any existing apex or `www` DNS records for `phaseplay.app` (for example old GitHub Pages records). The Worker's custom domain creates its own.
2. **Workers & Pages → Create → Import a repository** → pick this repo.
3. Settings:
   - **Project / Worker name:** `phaseplay` (must match `[env.production] name` in `apps/api/wrangler.toml`)
   - **Production branch:** `main` (every push to `main` deploys)
   - **Root directory:** `/` (the repo root; pnpm workspaces install from there)
   - **Build command:** `pnpm cf:build`
   - **Deploy command:** `pnpm cf:deploy` (not `pnpm deploy`, which is a built-in pnpm command)
   - Leave non-production branch builds **off** for now: passkeys only work on `phaseplay.app`, so preview URLs can't sign in.
4. Save and deploy. The first deploy creates the D1 database `phaseplay`, applies migrations, attaches `phaseplay.app` and `www.phaseplay.app`, and serves the app. A new custom domain's certificate can take a few minutes.

After that, **every push to `main` deploys to phaseplay.app**. Each build shows as a check on the GitHub commit. Protect `main` (Settings → Branches: require the CI checks to pass) so only green code reaches it, since Cloudflare deploys whatever lands on `main`.

**From a laptop instead:** `pnpm i`, then `pnpm --filter @phaseplay/api exec wrangler login`, then `pnpm cf:deploy`.

## Public demo

Anyone can try Phaseplay without an account: **Explore the demo** on the landing page, the sign-in page, or the shareable link https://phaseplay.app/demo. It signs the visitor in as "Sam Carter", the coach of the fictional **Phaseplay RFC** (30 players, practices, games, a 7s tournament, social events, a fundraiser, team sheets, plays, drills, practice plans and a recorded match).

- The server refuses every write from the demo account (`apps/api/src/app.ts`), including adding a passkey, so no visitor can change the demo or take the account over. The app applies demo edits on-device only and shows a banner with "Create your team".
- The demo team is generated by `apps/api/src/seed/demo.ts`. It is created on the first visit and refreshed by the nightly cron (and lazily when older than 20 h), so its dates always look current. The same generator powers `pnpm db:seed` locally.
- Local dev logins on `/signin`: Alex Morgan (writable coach) and Jess Taylor (player). Sam Carter is the read-only demo account.

## Rollback

`pnpm --filter @phaseplay/api exec wrangler rollback --env production` restores the previous Worker version (web and API together). Migrations are expand/contract, so the previous version works with the current schema. You can also roll back from the dashboard: Workers & Pages → phaseplay → Deployments. The nightly workflow smoke-tests production.

## Data

- Backups: D1 Time Travel (`wrangler d1 time-travel restore phaseplay --env production --timestamp <iso>`), 7 days on the free plan, 30 on Workers Paid.
- Free plan: fine for a handful of teams. Move to Workers Paid ($5/month) when D1 reads pass about half the 5M/day cap (roughly 5–8 active teams) or before a big tournament weekend; free limits are hard daily caps.

## Secrets

- `PUSH_KEY_SECRET` (optional, recommended): encrypts the stored push-notification signing key, so a copy of the database alone can't send notifications. Make a long random value (e.g. `openssl rand -base64 48`), then in the Cloudflare dashboard: Workers & Pages → phaseplay → Settings → Variables and Secrets → Add → type **Secret**, name `PUSH_KEY_SECRET` (or `pnpm --filter @phaseplay/api exec wrangler secret put PUSH_KEY_SECRET --env production`). The existing key is encrypted on the next notification send; nothing else changes.
- **Never change or delete it once set**: the stored key could no longer be read and notifications stop. Recovery: delete the `vapid` row from `server_keys`; a new key is made and everyone has to turn notifications on again.
